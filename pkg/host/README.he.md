# מצב ריבוי בוטים: כמה עוזרים על שרת אחד

כל בוט חדש רץ קודם על השרת הזה, מבודד לגמרי מהאחרים:

- תיקייה משלו: `/opt/agents/<שם>/` (הרשאות 700). בתוכה `.env` עם המפתחות (600), `data/memory.db`, `logs/`, ו-`wa-bridge/auth` (החיבור לוואטסאפ).
- משתמש לינוקס משלו (`agent-<שם>`). בוט אחד לא יכול לקרוא קבצים של בוט אחר.
- שלושה שירותים לכל בוט: `assistant-bot@<שם>` (המוח), `assistant-bridge@<שם>` (וואטסאפ), `assistant-setup@<שם>` (דף החיבורים). לכל אחד יש תקרת זיכרון ו-CPU.
- פורטים פנימיים מוקצים אוטומטית (מ-21000 והלאה, 3 לכל בוט, רק על 127.0.0.1).
- הקוד משותף ונמצא ב-`/opt/agents/_shared/`. עדכון קוד אחד מעדכן את כולם אחרי restart. בתיקייה המשותפת אין מפתחות של בוט.
- לכל בוט סודות משלו: סיסמת הגשר, קישור ההגדרות, והקבצים בתיקייה שלו. בוט אחד לא מקבל את הסודות של בוט אחר.

## התקנה חד-פעמית (לא בוצעה)
```
sudo bash host/install-host.sh --onboard-host setup.<domain>
```
הסקריפט לא מפעיל אף בוט ולא נוגע ב-Caddy או בשירותים קיימים. הוא מתקין את הקוד המשותף, את `agentsctl` ואת יחידות ה-systemd, ומפעיל שני דברים קטנים: טיימר מצב (כל 2 דק׳) ומאזין לבקשות מאתר ההקמה. הרצה נוספת מרעננת קוד ויחידות, ולא מוחקת בוט, רישום, או סודות שכבר נוצרו.

## ניהול
| פקודה | מה עושה |
|---|---|
| `agentsctl capacity` | כמה RAM ודיסק פנויים, וכמה בוטים נוספים נכנסים |
| `agentsctl create noa --bot-name נועה` | יוצר בוט ומדפיס קישור לדף החיבורים |
| `agentsctl list` | כל הבוטים ומצב השירותים שלהם |
| `agentsctl stop/start/restart noa` | עצירה, הפעלה או הפעלה מחדש |
| `agentsctl delete noa --yes` | מחיקה, עם גיבוי ל-`/opt/agents/_archive` (עם `--purge` בלי גיבוי) |
| `agentsctl link noa [--new]` | קישור לדף החיבורים (`--new` יוצר קישור חדש ומבטל את הישן) |
| `agentsctl invite --count 3` | קודי הזמנה חד-פעמיים לאתר ההקמה |
| `agentsctl export noa /var/backups/noa.tar.gz` | חבילה למעבר לשרת משלו (`install.sh --restore`) |
| `agentsctl status` | מצב בריאות של כולם |
| `agentsctl release-access noa` | מנתק את המפעיל מהבוט הזה: מוחק מפתחות SSH של המפעיל, מחליף סודות מקומיים לערכים חדשים שנשארים רק על השרת, ומוחק כתובת של מנהל. הרצה שנייה לא מחליפה סודות שוב |
| `agentsctl check-isolation` | בודק שלכל בוט סודות משלו, בלי להדפיס אותם |

## קובץ מצב (בלי תוכן)
כל בוט כותב `status.json` פעם בדקה בתיקייה שלו. `agentsctl status --write` מעתיק ממנו רק את השדות שברשימה ל-`/opt/agents/_status/<שם>.json` ול-`index.json`:
פועל/לא, וואטסאפ מחובר, Google מחובר, יש מפתח OpenAI, עלות היום והחודש, תקרה, ומצב השירותים.
אין בקבצים האלה הודעות, מיילים, זיכרונות או מפתחות. `routes.json` מכיל רק שם→פורט של דף החיבורים.

## כמה בוטים השרת הנוכחי מחזיק
מדדתי על השרת הזה (9.11.2026): 2 vCPU, ‏3.8GB RAM, בלי swap, ‏18GB דיסק פנוי. השירותים הקיימים תופסים כ-1.3GB, ונשארים בערך 2.5GB זמינים.

לכל בוט בערך 380MB: המוח כ-180MB, וואטסאפ כ-160MB ודף החיבורים כ-40MB. בדיסק כ-300MB לכל בוט, ועוד כ-1GB חד-פעמי לקוד המשותף.

- **היום: 4 בוטים בערך**, עם שמירה של 700MB פנויים לשירותים הקיימים. דיסק הוא לא המגבלה.
- אם מוסיפים swap של 2GB, אפשר בערך 5–6 בוטים, אבל אז עלולה להיות איטיות בעומס.
- בשרת של 8GB (למשל CX33 ב-Hetzner) נכנסים בערך 15 בוטים. בשרת של 16GB בערך 35.
- `agentsctl create` בודק מקום לפני כל יצירה ומסרב כשאין (אפשר לעקוף עם `--force`).

המעבד בדרך כלל לא מהווה מגבלה, כי רוב הזמן הבוטים מחכים להודעות. העבודה הכבדה (המודל) רצה אצל OpenAI.

## ניתוק המפעיל
`agentsctl release-access <שם>` רץ כ-root. הבוט עצמו מפעיל את אותו דבר בלי הרשאת root: הוא יוצר את הקובץ `/opt/agents/<שם>/.release-request`, ויחידת systemd מריצה את הפקודה עבור השם הזה בלבד.

מפתח SSH של המפעיל צריך להופיע עם ההערה `assistant-operator` ועם שם הבוט. מפתח בלי ההערה הזו נשאר.

## שרת משלך
`install.sh` הוא התקנת שרת משלך. ברירת המחדל היא `SELF_HOST=1`. ההתקנה לא כותבת כתובת מנהל, מדווח מצב, פעימת לב החוצה, או וו לבקשות לצוות, ולא מקבלת מפתח API.

העברת הבעלות על השרת נעשית במסך של Hetzner, בלי מפתח. השלבים: `hetzner-transfer.md`.

## בדיקה בלי שרת
`bash host/check-selfhost.sh` מריץ shellcheck, בדיקת בידוד, והרצה יבשה של `install.sh`. אם אין docker או podman, ההרצה היבשה רצה בלי קונטיינר ובלי root, ובודקת שביחידות שנוצרו אין חיבור למנהל.
